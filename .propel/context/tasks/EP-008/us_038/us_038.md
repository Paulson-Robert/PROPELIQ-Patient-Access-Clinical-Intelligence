# User Story - US_038

## Story ID

- ID Format: US_038

## Story Title

- Data Aggregation and 360-Degree Patient View

## Description

- As a **staff member**, I want the system to aggregate extracted clinical data from all of a patient's documents into a single de-duplicated 360-Degree Patient View with human-in-the-loop verification, so that I can review a consolidated clinical summary in under 2 minutes.

## Acceptance Criteria

### AC-01: Aggregation merges data from all processed documents

- **Given**: A patient has multiple documents with completed extractions
- **When**: The aggregation engine runs (triggered after each extraction completion)
- **Then**: The PatientView record is created or updated with AggregatedVitals, AggregatedMedications, AggregatedAllergies, AggregatedDiagnoses, and AggregatedProcedures JSONB fields containing merged data from all source documents

### AC-02: De-duplication removes matching entities

- **Given**: Two documents contain the same medication (e.g., "Lisinopril 10mg" from both Document A and Document B)
- **When**: Aggregation runs
- **Then**: The medication appears once in AggregatedMedications with references to both source documents, not duplicated

### AC-03: 360-Degree Patient View renders within 2 minutes of document processing

- **Given**: A patient's latest document has completed extraction
- **When**: The staff member opens the 360-Degree Patient View (SCR-019)
- **Then**: The consolidated view is available within 2 minutes of the extraction completing (NFR-002), displaying vitals, medications, allergies, diagnoses, and procedures in organized sections

### AC-04: Human-in-the-loop verification required before clinical use

- **Given**: The 360-Degree Patient View displays aggregated data
- **When**: The staff member reviews the view
- **Then**: All AI-generated data is marked as "Unverified" until the staff member explicitly verifies each section, and the VerificationStatus field tracks the verification state

### AC-05: Source document provenance is traceable

- **Given**: A data point appears in the 360-Degree Patient View
- **When**: The staff member clicks on the data point
- **Then**: The system displays the source document(s) that contributed that data point with document name, upload date, and extraction confidence

### AC-06: Empty view for patients with no processed documents

- **Given**: A patient has no processed documents
- **When**: The staff member opens the 360-Degree Patient View
- **Then**: The system displays a zero-state message "No clinical data available. Awaiting document uploads and processing."

## Edge Cases

- **Aggregation during active extraction**: If a new document is being extracted while aggregation runs, the aggregation should complete with currently available data and re-run after the new extraction completes
- **Conflicting data detected during aggregation**: When the aggregation engine detects conflicting values for the same field across documents, it should create DataConflict records rather than silently choosing one value
- **Very large patient record**: If a patient has 50+ documents, the aggregation should complete within the 2-minute NFR threshold; if performance degrades, incremental aggregation should be used
