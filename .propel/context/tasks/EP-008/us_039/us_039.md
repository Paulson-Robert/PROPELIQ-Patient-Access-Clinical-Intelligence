# User Story - US_039

## Story ID

- ID Format: US_039

## Story Title

- Clinical Data Conflict Detection and Resolution

## Description

- As a **staff member**, I want the system to detect conflicting clinical data across documents and highlight them with visual indicators and source references, so that I can resolve discrepancies and ensure accurate patient records.

## Acceptance Criteria

### AC-01: Conflicts are detected during data aggregation

- **Given**: Two or more documents contain different values for the same clinical field (e.g., Document A: "Lisinopril 10mg", Document B: "Lisinopril 20mg")
- **When**: The aggregation engine processes the patient's extracted data
- **Then**: A DataConflict record is created with ConflictType, FieldName, both values, both source document IDs, and ResolutionStatus "Open"

### AC-02: Conflicts are highlighted in the 360-Degree Patient View

- **Given**: The patient has open DataConflict records
- **When**: The staff member views the 360-Degree Patient View (SCR-019)
- **Then**: Conflicting fields are highlighted with an amber border, tinted background, and AlertTriangle icon (UXR-404), with a "Resolve" action button

### AC-03: Staff resolves conflict by selecting correct value

- **Given**: A conflict is highlighted in the patient view
- **When**: The staff member clicks "Resolve" and selects one of the conflicting values or enters a corrected value on SCR-020
- **Then**: The DataConflict status changes to "Resolved", the PatientView is updated with the resolved value, and an AuditLog entry is created recording the resolution

### AC-04: Multi-document conflicts display all values

- **Given**: Three or more documents contain conflicting values for the same field
- **When**: The conflict resolution interface is opened (SCR-020)
- **Then**: All conflicting values are displayed with their respective source documents, allowing the staff member to select or enter the correct value

### AC-05: Pending Clinical Review option for unresolvable conflicts

- **Given**: A staff member encounters a conflict they cannot resolve
- **When**: The staff member selects "Mark for Clinical Review"
- **Then**: The conflict status changes to "Pending Clinical Review", and the conflict remains highlighted in the patient view until a provider resolves it

### AC-06: Conflict resolution is audit-logged

- **Given**: A staff member resolves a conflict
- **When**: The resolution is saved
- **Then**: An immutable AuditLog entry is created with the actor ID, timestamp, conflict ID, selected value, and resolution notes

## Edge Cases

- **Conflict on resolved field**: If a new document introduces a value conflicting with an already-resolved field, the system should create a new DataConflict record (not reopen the old one)
- **Identical values from different sources**: Two documents with the same value for the same field should not be flagged as a conflict — they should be treated as corroborating evidence
- **Bulk conflict resolution**: If a patient has 10+ open conflicts, the staff member should be able to resolve them in sequence without navigating back to the patient view between each resolution
