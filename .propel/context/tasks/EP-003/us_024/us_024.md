# User Story - US_024

## Story ID

- ID Format: US_024

## Story Title

- Same-Day Queue Management and Arrival Marking

## Description

- As a **staff member**, I want to view and manage the same-day appointment queue, mark patients as "Arrived" when they check in, and reorder queue entries via drag-and-drop, so that I can efficiently manage patient flow at the front desk.

## Acceptance Criteria

### AC-01: Same-day queue displays all today's appointments

- **Given**: The staff member navigates to the same-day queue page (SCR-017)
- **When**: The page loads
- **Then**: The system displays all appointments for the current day with patient name, appointment time, provider, status (Scheduled/Arrived/Completed), booking type badge (Scheduled/Walk-in), and estimated wait time

### AC-02: Staff marks patient as "Arrived"

- **Given**: A patient with a "Scheduled" appointment arrives at the front desk
- **When**: The staff member clicks the "Mark Arrived" button for that patient
- **Then**: The appointment status changes to "Arrived" with an arrival timestamp recorded, and the queue display updates in real-time to reflect the status change

### AC-03: Already-arrived patients cannot be marked again

- **Given**: A patient's appointment is already in "Arrived" status
- **When**: The staff member views that queue entry
- **Then**: The "Mark Arrived" button is disabled or replaced with the arrival timestamp, preventing duplicate actions

### AC-04: Cancelled appointments prevent arrival marking

- **Given**: An appointment in the queue has "Cancelled" status
- **When**: The staff member views that queue entry
- **Then**: The "Mark Arrived" button is disabled and the entry displays "Cancelled" status with a visual strike-through or greyed-out appearance

### AC-05: Queue reordering via drag-and-drop on desktop

- **Given**: The staff member is on the same-day queue page on a desktop browser
- **When**: The staff member drags a queue entry's handle to a new position
- **Then**: The queue order is updated and persisted, reflecting the staff member's prioritization

### AC-06: Queue reordering via long-press on mobile

- **Given**: The staff member is on the same-day queue page on a mobile device
- **When**: The staff member long-presses a queue entry and moves it to a new position
- **Then**: The queue order is updated and persisted, matching the drag-and-drop desktop behavior

### AC-07: Patient not in queue triggers walk-in flow

- **Given**: A patient arrives who is not in the same-day queue
- **When**: The staff member searches the queue and finds no matching patient
- **Then**: The system displays a "Patient not found — Create Walk-in" action linking to the walk-in booking flow (US_023)

## Edge Cases

- **Queue display during rapid arrivals**: If multiple staff members mark different patients as arrived simultaneously, all status changes should be reflected without conflicts or data loss
- **Queue refresh on network interruption**: If the network drops while viewing the queue, the system should display a stale-data warning and refresh automatically when connectivity is restored
- **Empty queue**: If no appointments exist for the current day, the queue should display a "No patients scheduled for today" empty state
