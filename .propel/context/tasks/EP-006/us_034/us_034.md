# User Story - US_034

## Story ID

- ID Format: US_034

## Story Title

- Document Retention and Patient-Initiated Deletion

## Description

- As a **patient**, I want my uploaded clinical documents to be retained indefinitely until I explicitly request deletion, at which point all documents and extracted data are permanently and irrecoverably removed, so that my data is available when needed and I can exercise my right to delete.

## Acceptance Criteria

### AC-01: Documents are retained indefinitely by default

- **Given**: A patient has uploaded clinical documents
- **When**: Time passes without a deletion request
- **Then**: All documents remain accessible in the document list (SCR-012) with no automatic expiration or archival

### AC-02: Patient can request deletion of individual documents

- **Given**: The patient views their document list on SCR-012
- **When**: The patient clicks "Delete" on a specific document and confirms via a deletion confirmation dialog
- **Then**: The document file, all associated ExtractedDataRecord entries, related DataConflict entries, and MedicalCodeMapping entries sourced from that document are permanently removed

### AC-03: Patient can request deletion of all documents

- **Given**: The patient views their document list on SCR-012
- **When**: The patient clicks "Delete All Documents" and confirms with a typed confirmation (e.g., "DELETE ALL")
- **Then**: All clinical documents, extracted records, conflicts, code mappings, and the PatientView aggregated data are permanently and irrecoverably removed

### AC-04: Deletion triggers PatientView re-aggregation

- **Given**: A patient has a PatientView generated from multiple documents
- **When**: One document is deleted (not all)
- **Then**: The PatientView is re-aggregated from remaining documents, removing data sourced exclusively from the deleted document

### AC-05: Deletion is audit-logged

- **Given**: A document deletion is executed
- **When**: The deletion completes
- **Then**: An AuditLog entry is created recording the actor (patient), timestamp, document ID, and action type "DocumentDeleted" — without storing the deleted document's content in the audit log

## Edge Cases

- **Delete during active processing**: If a document is currently being processed (status: Scanning or Processing) and the patient requests deletion, the system should cancel the processing job before deleting the document
- **Last document deletion**: Deleting the only document for a patient should clear the PatientView entirely and display an empty state on SCR-019
- **Deletion of document involved in open conflicts**: If the document being deleted is referenced by unresolved DataConflict entries, those conflicts should be auto-resolved (the conflicting value from the deleted document is removed) and staff should be notified
