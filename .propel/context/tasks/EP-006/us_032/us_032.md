# User Story - US_032

## Story ID

- ID Format: US_032

## Story Title

- Clinical Document Upload and Validation

## Description

- As a **patient**, I want to upload clinical documents in supported formats (PDF, DOCX, JPG, PNG, DICOM, HL7/FHIR) with file size and format validation providing clear rejection messages, so that my medical records can be processed for the 360-Degree Patient View.

## Acceptance Criteria

### AC-01: Multi-format file upload via drag-and-drop or file picker

- **Given**: The patient navigates to the document upload page (SCR-011)
- **When**: The patient drags files onto the drop zone or clicks "Browse Files" to select files
- **Then**: The system accepts one or more files and begins the upload process, displaying an upload progress indicator for each file

### AC-02: Supported format validation accepts valid files

- **Given**: The patient selects files for upload
- **When**: The files are in supported formats (PDF, DOCX, JPG, PNG, DICOM, HL7/FHIR)
- **Then**: The files pass format validation and proceed to the upload stage

### AC-03: Unsupported format shows specific rejection

- **Given**: The patient selects a file in an unsupported format (e.g., .exe, .xlsx)
- **When**: The file format validation runs
- **Then**: The system rejects the file with an inline error (UXR-604) showing "File format not supported. Accepted formats: PDF, DOCX, JPG, PNG, DICOM, HL7/FHIR" and the file is not uploaded

### AC-04: File size validation enforces 50MB limit

- **Given**: The patient selects a file larger than 50MB
- **When**: The file size validation runs
- **Then**: The system rejects the file with an error showing "File exceeds the maximum size of 50MB" and the file is not uploaded

### AC-05: Upload progress is displayed in real-time

- **Given**: Valid files are being uploaded
- **When**: The upload is in progress
- **Then**: Each file shows a progress bar with percentage complete, and on completion transitions to a "Pending Scan" status indicator

### AC-06: Multiple files can be uploaded in a single session

- **Given**: The patient has multiple clinical documents to upload
- **When**: The patient selects or drags multiple files
- **Then**: All valid files are uploaded concurrently (or sequentially) with individual progress tracking and validation applied to each file independently

## Edge Cases

- **Mixed valid and invalid files**: If a batch contains both valid and invalid files, the valid files should proceed to upload while invalid files show individual rejection messages
- **Upload interrupted by network loss**: If the network drops during upload, the system should display a "Upload failed — check your connection and try again" message without losing the file selection
- **Zero-byte file**: A file with zero bytes should be rejected with "File is empty or corrupted" error
- **Filename with special characters**: Files with Unicode characters, spaces, or long filenames should be handled correctly without truncation or encoding errors
