# User Story - US_033

## Story ID

- ID Format: US_033

## Story Title

- Malware Scanning and Document Processing Pipeline Status

## Description

- As a **patient**, I want all uploaded documents to be scanned for malware before processing, with real-time pipeline status tracking displayed as a step indicator, so that I am protected from malicious files and can see the processing progress of my documents.

## Acceptance Criteria

### AC-01: ClamAV malware scan runs on every uploaded document

- **Given**: A document has been uploaded successfully
- **When**: The document enters the processing pipeline
- **Then**: The system scans the document using ClamAV (via nClam) and updates the MalwareScanStatus to "Clean" or "Infected"

### AC-02: Malware-infected file is quarantined and rejected

- **Given**: A document is scanned and malware is detected
- **When**: The scan completes with a positive result
- **Then**: The system quarantines the file (moves to isolated storage), updates the document status to "Rejected — Malware Detected", and notifies the patient with "File rejected for security reasons — please upload a clean file"

### AC-03: Pipeline status step indicator shows all stages

- **Given**: A document has been uploaded and is being processed
- **When**: The patient views the document list page (SCR-012)
- **Then**: A horizontal step indicator (UXR-403) displays the pipeline stages: Uploaded → Scanning → Processing → Completed, with the current stage highlighted

### AC-04: Clean document is queued for data extraction

- **Given**: A document passes the malware scan (status: Clean)
- **When**: The scan completes
- **Then**: The document is queued as a Hangfire job for clinical data extraction and the pipeline status advances to "Processing"

### AC-05: Malware scan service unavailability queues for retry

- **Given**: The ClamAV service is temporarily unavailable
- **When**: A document scan is attempted
- **Then**: The system queues the file for retry, displays "Pending Scan" status to the patient, and retries with exponential backoff (max 3 attempts)

### AC-06: Failed extraction flags document for manual review

- **Given**: A document passes malware scan but data extraction fails
- **When**: The extraction pipeline encounters an error
- **Then**: The document status is updated to "Failed", the patient is notified "Document processing failed — our team will review this document manually", and the document is flagged for staff review

## Edge Cases

- **Large file scan timeout**: If ClamAV takes longer than 60 seconds to scan a file, the system should time out the scan, mark the document as "Scan Timeout", and retry
- **ClamAV virus definition update during scan**: If virus definitions are updated while a batch of files is being scanned, the scan should complete with the definitions available at scan start; newly updated definitions apply to subsequent scans
- **Document resubmission**: If a patient re-uploads the same file (by content hash), the system should accept it as a new document and run the full pipeline again rather than deduplicating
