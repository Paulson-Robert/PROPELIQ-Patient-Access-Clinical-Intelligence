# User Story - US_014

## Story ID

- ID Format: US_014

## Story Title

- Staff and Admin MFA Authentication

## Description

- As a **staff member or admin**, I want to authenticate via email/password with mandatory multi-factor authentication (TOTP or SMS code), so that my account is protected with an additional security layer as required by HIPAA.

## Acceptance Criteria

### AC-01: Staff login with MFA completes successfully

- **Given**: A staff user with an active account and configured MFA device
- **When**: The staff user enters valid email/password and then a valid TOTP or SMS code
- **Then**: The system issues a JWT session token with 15-minute sliding expiry and Staff role permissions, and redirects to the staff dashboard (SCR-003)

### AC-02: Admin login with MFA completes successfully

- **Given**: An admin user with an active account and configured MFA device
- **When**: The admin enters valid email/password and then a valid TOTP or SMS code
- **Then**: The system issues a JWT session token with 15-minute sliding expiry and Admin role permissions, and redirects to the admin dashboard (SCR-004)

### AC-03: First-login MFA setup flow

- **Given**: A staff or admin user logs in for the first time without an MFA device configured
- **When**: The user completes credential verification
- **Then**: The system redirects to the MFA setup page (SCR-027) where the user can scan a QR code for TOTP or configure SMS-based MFA, and must complete MFA verification before accessing the platform

### AC-04: Invalid MFA code after 3 attempts terminates session

- **Given**: A staff or admin user has entered valid credentials and is on the MFA verification step (SCR-026)
- **When**: The user enters an invalid MFA code three times consecutively
- **Then**: The session is terminated, the user is redirected to the login page with a "Too many failed attempts — please log in again" message

### AC-05: Expired MFA code prompts re-send

- **Given**: A staff or admin user is on the MFA verification step
- **When**: The TOTP code has expired (30-second window) or the SMS code has timed out
- **Then**: The system displays "Code expired" with a "Request new code" button that sends a fresh SMS code or prompts the user to generate a new TOTP code

### AC-06: Deactivated account is rejected at login

- **Given**: An admin has deactivated a staff account
- **When**: The deactivated user attempts to log in
- **Then**: The system rejects the login with "Your account has been disabled. Contact your administrator." and does not proceed to MFA

## Edge Cases

- **MFA device lost**: If a user cannot access their MFA device, they must contact an admin for MFA reset — the system should not provide a self-service bypass
- **Concurrent sessions**: If a staff user logs in from a new device, existing sessions should remain valid until they expire naturally (no forced single-session)
- **Clock skew**: TOTP validation should accept codes within a ±1 time step window (±30 seconds) to account for clock drift between server and authenticator app
