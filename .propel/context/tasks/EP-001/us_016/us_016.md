# User Story - US_016

## Story ID

- ID Format: US_016

## Story Title

- Password Security and Account Lockout

## Description

- As a **platform user**, I want the system to enforce password complexity requirements and lock my account after 5 consecutive failed login attempts, so that my credentials are protected against brute-force attacks and weak passwords.

## Acceptance Criteria

### AC-01: Password complexity is enforced on registration

- **Given**: A patient or staff/admin user is creating or changing a password
- **When**: The user submits a password that does not meet complexity requirements (minimum 8 characters, at least one uppercase, one lowercase, one digit, one special character)
- **Then**: The system rejects the password with specific inline validation errors indicating which requirements are not met

### AC-02: Passwords are hashed with bcrypt work factor 12

- **Given**: A user creates or changes their password
- **When**: The password is stored in the database
- **Then**: The stored value is a bcrypt hash with a minimum work factor of 12, and no plaintext or reversibly encrypted password is ever persisted

### AC-03: Account locks after 5 consecutive failed login attempts

- **Given**: A user has entered incorrect credentials 4 times consecutively
- **When**: The user enters incorrect credentials a 5th time
- **Then**: The account is locked, the system displays "Your account has been locked due to too many failed login attempts. Please reset your password or contact your administrator." and subsequent login attempts are rejected

### AC-04: Password reset flow unlocks account

- **Given**: A patient account is locked due to failed login attempts
- **When**: The patient completes the password reset flow via email link (SCR-029)
- **Then**: The account is unlocked, the failed attempt counter is reset to zero, and the patient can log in with the new password

### AC-05: Failed attempt counter resets on successful login

- **Given**: A user has 3 consecutive failed login attempts
- **When**: The user enters correct credentials on the 4th attempt
- **Then**: The failed attempt counter resets to zero and the login succeeds normally

## Edge Cases

- **Staff/admin account lockout**: Staff and admin accounts locked by failed attempts can be unlocked by an admin through user management (UC-018) in addition to password reset
- **Timing attack prevention**: Login response times should be consistent regardless of whether the email exists in the system (prevent user enumeration)
- **Password reuse**: The system should not enforce password history checks in Phase 1 but should store the infrastructure to support it in a future phase
