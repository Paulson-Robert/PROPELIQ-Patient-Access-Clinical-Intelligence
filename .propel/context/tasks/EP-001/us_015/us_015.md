# User Story - US_015

## Story ID

- ID Format: US_015

## Story Title

- Session Management and Role-Based Access Control

## Description

- As a **platform user**, I want the system to enforce JWT session tokens with 15-minute sliding expiry and role-based access control restricting access to authorized features only, so that my session is secure and I can only access functionality appropriate to my role.

## Acceptance Criteria

### AC-01: JWT token issued with correct claims and 15-minute expiry

- **Given**: A user has successfully authenticated (any role)
- **When**: The system issues a JWT session token
- **Then**: The token contains the user's ID, email, role (Patient/Staff/Admin), and an expiry set to 15 minutes from issuance, signed with the server's private key

### AC-02: Sliding expiry extends on authenticated requests

- **Given**: A user has an active JWT session token with 5 minutes remaining
- **When**: The user makes an authenticated API request
- **Then**: The session expiry is extended by 15 minutes from the time of the request

### AC-03: Patient role is restricted to patient-only endpoints

- **Given**: A user with the Patient role has an active session
- **When**: The patient attempts to access a staff-only endpoint (e.g., queue management) or admin-only endpoint (e.g., user management)
- **Then**: The system returns HTTP 403 Forbidden

### AC-04: Staff role is restricted to staff-authorized endpoints

- **Given**: A user with the Staff role has an active session
- **When**: The staff user attempts to access an admin-only endpoint (e.g., audit log viewer, user management)
- **Then**: The system returns HTTP 403 Forbidden

### AC-05: Admin role has full access

- **Given**: A user with the Admin role has an active session
- **When**: The admin accesses any platform endpoint
- **Then**: The system grants access to all endpoints including admin-only, staff-only, and patient-only resources

### AC-06: Expired token returns 401 and triggers client redirect

- **Given**: A user's JWT session token has expired (no activity for 15+ minutes)
- **When**: The user attempts any API request
- **Then**: The system returns HTTP 401 Unauthorized and the frontend redirects to the login page with a "Session expired" toast message

## Edge Cases

- **Token tampering**: If a JWT token is modified (claims altered), the signature validation should fail and the system should return HTTP 401
- **Role change mid-session**: If an admin changes a user's role while the user has an active session, the role change takes effect on the next token refresh, not immediately
- **Simultaneous role claims**: A user should have exactly one role — the system should reject tokens with multiple role claims
