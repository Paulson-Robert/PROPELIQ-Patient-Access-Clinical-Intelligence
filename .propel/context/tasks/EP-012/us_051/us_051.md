# User Story - US_051

## Story ID

- ID Format: US_051

## Story Title

- Responsive Breakpoints and Layout Transformations

## Description

- As a **platform user**, I want the interface to implement responsive breakpoints at 375px, 768px, 1024px, and 1440px with layout transformations (sidebar collapse to bottom nav, data tables to stacked cards) so that the platform is usable across mobile, tablet, and desktop devices.

## Acceptance Criteria

### AC-01: Breakpoints are configured at specified widths

- **Given**: TailwindCSS is configured with custom breakpoints
- **When**: The viewport width changes
- **Then**: Layout changes trigger at 375px (mobile), 768px (tablet), 1024px (desktop), and 1440px (wide desktop) per UXR-301

### AC-02: Sidebar collapses to bottom nav on mobile

- **Given**: A user is viewing the platform on a viewport below 768px
- **When**: The layout renders
- **Then**: The sidebar navigation is completely hidden and replaced by a bottom navigation bar pinned to the viewport bottom (UXR-302)

### AC-03: Data tables transform to stacked cards on mobile

- **Given**: A page contains a data table (e.g., appointment history, audit log, user management)
- **When**: The viewport is below 768px
- **Then**: The table transforms into a stacked card layout where each row becomes a card with key data points displayed as label-value pairs (UXR-303)

### AC-04: Form layouts adapt to mobile viewport

- **Given**: A page contains a multi-column form (e.g., intake form, insurance form)
- **When**: The viewport is below 768px
- **Then**: Form columns stack vertically with full-width inputs and maintained field ordering

### AC-05: Wide desktop utilizes additional space

- **Given**: A user views the platform on a viewport ≥1440px
- **When**: The layout renders
- **Then**: Content areas use the additional space appropriately (wider content area, sidebar remains fixed width, no content stretching beyond readable line length)

## Edge Cases

- **Viewport resize during interaction**: If the user resizes the browser while filling a form or dragging a queue item, the layout should transition smoothly without losing input state or drag context
- **Print layout**: When printing a page (e.g., audit log, patient view), the print stylesheet should use a single-column layout regardless of the current viewport
- **Landscape mobile**: On landscape-oriented mobile devices (e.g., 667px × 375px), the layout should use the tablet breakpoint rather than the mobile breakpoint
