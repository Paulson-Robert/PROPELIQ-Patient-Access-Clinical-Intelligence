# User Story - US_049

## Story ID

- ID Format: US_049

## Story Title

- Design System and Component Library Setup

## Description

- As a **developer**, I want the Shadcn UI component library integrated with TailwindCSS design tokens, Lucide icons, and consistent 4px-base spacing applied across all UI components, so that all feature epics build on a unified, design-system-compliant visual foundation.

## Acceptance Criteria

### AC-01: Shadcn UI initialized with custom design tokens

- **Given**: The frontend scaffold (US_001) exists
- **When**: Shadcn UI is configured via its CLI
- **Then**: The component library is initialized with the project's design tokens (primary, secondary, destructive, muted color palettes; border-radius; font family) matching the design system specification

### AC-02: TailwindCSS spacing scale uses 4px base unit

- **Given**: TailwindCSS is configured
- **When**: A developer uses spacing utilities (p-1, m-2, gap-4, etc.)
- **Then**: The spacing scale follows the 4px base unit system (p-1 = 4px, p-2 = 8px, p-4 = 16px) as defined in UXR-401

### AC-03: Lucide icons are available with consistent sizing

- **Given**: The icon library is integrated
- **When**: A developer imports and renders a Lucide icon
- **Then**: Icons render at the configured default size (16px for inline, 20px for buttons, 24px for navigation) with consistent stroke weight across all usage contexts

### AC-04: Mobile-first responsive base styles are applied

- **Given**: The design system is configured
- **When**: Base styles are applied to the application shell
- **Then**: All components render in a mobile-first layout by default (UXR-001), with fluid scaling that responds to viewport changes

### AC-05: Component variants match design system specification

- **Given**: Shadcn UI components (Button, Input, Card, Dialog, Table, Badge, Toast) are imported
- **When**: Components are rendered with their default variant
- **Then**: Each component matches the design system's visual specification for color, typography, border-radius, and spacing

## Edge Cases

- **Design token override conflicts**: If a developer overrides a design token in a component-level style, the override should take precedence but a lint warning should be generated if it deviates from the system
- **Missing icon**: If a Lucide icon name is misspelled or does not exist, the build should produce a clear error rather than rendering a blank space
- **Dark mode preparation**: While dark mode is not in Phase 1 scope, the design token structure should support a future `dark` variant without requiring token restructuring
