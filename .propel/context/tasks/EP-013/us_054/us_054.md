# User Story - US_054

## Story ID

- ID Format: US_054

## Story Title

- ARIA Labels, Touch Targets, and Non-Color Encoding

## Description

- As a **platform user**, I want all complex widgets to have proper ARIA labels and roles, all touch targets to meet the 44x44px minimum on mobile, and all color-coded indicators to include redundant icon or text labels, so that the platform is usable by assistive technology users and touch device users.

## Acceptance Criteria

### AC-01: ARIA labels on complex widgets

- **Given**: A complex widget exists on a page (data table, modal dialog, chat interface, dropdown menu, tab panel, toast notification)
- **When**: A screen reader encounters the widget
- **Then**: The widget has appropriate ARIA roles (role="dialog", role="table", role="tabpanel"), aria-label or aria-labelledby for identification, and aria-describedby for supplementary instructions per UXR-204

### AC-02: ARIA live regions for dynamic content

- **Given**: Content updates dynamically (toast notifications, chat messages, form validation errors, status changes)
- **When**: The content changes
- **Then**: An aria-live region (polite or assertive as appropriate) announces the change to screen readers without requiring the user to navigate to the updated area

### AC-03: Touch targets meet 44x44px minimum on mobile

- **Given**: An interactive element (button, link, checkbox, icon button) is rendered on a mobile viewport (<768px)
- **When**: The element's tap target area is measured
- **Then**: The tap target is at minimum 44x44px per UXR-205, with adequate spacing between adjacent targets to prevent accidental activation

### AC-04: Color-coded indicators include redundant encoding

- **Given**: A color-coded indicator is displayed (no-show risk tier, document status, appointment status, confidence level)
- **When**: The indicator renders
- **Then**: The indicator includes redundant encoding beyond color — icon (e.g., shield-check, alert-triangle) AND text label (e.g., "Low", "Medium", "High") per UXR-206

### AC-05: Form labels are programmatically associated

- **Given**: A form field exists on any page
- **When**: A screen reader focuses on the input
- **Then**: The input has a programmatically associated label (via htmlFor/id or aria-labelledby), required state is communicated (aria-required), and any validation error is associated via aria-describedby

### AC-06: Image alternatives are provided

- **Given**: A meaningful image or icon is displayed
- **When**: A screen reader encounters the image
- **Then**: The image has an appropriate alt attribute describing its purpose, or aria-hidden="true" if the image is purely decorative

## Edge Cases

- **Icon-only buttons**: Buttons that display only an icon (e.g., close, delete, edit) must have an aria-label describing the action (e.g., aria-label="Close dialog")
- **Dense data tables**: On mobile, when tables transform to cards, ARIA roles should update from table/row/cell to list/listitem to match the visual presentation
- **Drag-and-drop alternatives**: The queue reordering drag-and-drop (UXR-506) must have a keyboard alternative (e.g., arrow keys or "Move up"/"Move down" buttons) for users who cannot use a mouse
