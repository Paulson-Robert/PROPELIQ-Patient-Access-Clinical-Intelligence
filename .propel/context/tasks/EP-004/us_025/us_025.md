# User Story - US_025

## Story ID

- ID Format: US_025

## Story Title

- Google Calendar Sync Integration

## Description

- As a **patient**, I want to connect my Google Calendar so that booked, rescheduled, and cancelled appointments are automatically synchronized as calendar events, keeping my external calendar up to date.

## Acceptance Criteria

### AC-01: Patient initiates Google Calendar OAuth consent

- **Given**: The patient navigates to the calendar sync settings (SCR-013)
- **When**: The patient clicks "Connect Google Calendar"
- **Then**: The system redirects to the Google OAuth 2.0 consent screen requesting calendar read/write permissions

### AC-02: OAuth tokens are stored securely on consent

- **Given**: The patient grants Google Calendar permissions
- **When**: The OAuth flow completes
- **Then**: The system stores the access token and refresh token in the CalendarSync table with encrypted columns, marks the sync as active, and displays "Google Calendar Connected" on SCR-013

### AC-03: Existing appointments are synced on first connect

- **Given**: The patient has upcoming appointments and has just connected Google Calendar
- **When**: The sync is activated
- **Then**: A background job creates Google Calendar events for all upcoming appointments with correct date, time, provider, and location details

### AC-04: New bookings create calendar events automatically

- **Given**: The patient has an active Google Calendar sync
- **When**: The patient books a new appointment
- **Then**: A calendar event is created in the patient's Google Calendar asynchronously via a Hangfire background job

### AC-05: Cancellations and reschedules update calendar events

- **Given**: The patient has an active Google Calendar sync
- **When**: An appointment is cancelled or rescheduled
- **Then**: The corresponding Google Calendar event is deleted (cancellation) or updated (reschedule) via a background job

### AC-06: Token refresh handles expiry transparently

- **Given**: The patient's Google OAuth access token has expired
- **When**: A calendar sync operation is attempted
- **Then**: The system uses the refresh token to obtain a new access token without user intervention; if the refresh token is also expired, the patient is notified to re-authorize

### AC-07: Patient can disconnect Google Calendar

- **Given**: The patient has an active Google Calendar sync
- **When**: The patient clicks "Disconnect Google Calendar" on SCR-013
- **Then**: The sync is deactivated, stored tokens are deleted, and future appointment changes are no longer synced (existing calendar events are not removed)

## Edge Cases

- **OAuth consent denied**: If the patient denies Google Calendar permissions, the system returns to SCR-013 with "Calendar sync not enabled" and the booking flow is unaffected
- **Calendar event creation failure**: If event creation fails (API error, quota exceeded), the job is retried with exponential backoff (max 3 attempts); on permanent failure, the patient is not blocked but the sync status shows a warning
- **Google API rate limits**: If rate limits are hit, jobs are queued with backoff and processed within available quota
