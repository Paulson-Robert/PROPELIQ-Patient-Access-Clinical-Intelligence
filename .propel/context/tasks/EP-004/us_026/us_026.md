# User Story - US_026

## Story ID

- ID Format: US_026

## Story Title

- Microsoft Outlook Calendar Sync Integration

## Description

- As a **patient**, I want to connect my Microsoft Outlook calendar so that booked, rescheduled, and cancelled appointments are automatically synchronized as calendar events via the Microsoft Graph API.

## Acceptance Criteria

### AC-01: Patient initiates Microsoft OAuth consent

- **Given**: The patient navigates to the calendar sync settings (SCR-013)
- **When**: The patient clicks "Connect Outlook Calendar"
- **Then**: The system redirects to the Microsoft OAuth 2.0 consent screen requesting Calendars.ReadWrite permission via Microsoft Graph API

### AC-02: OAuth tokens are stored securely on consent

- **Given**: The patient grants Microsoft calendar permissions
- **When**: The OAuth flow completes
- **Then**: The system stores the access token and refresh token in the CalendarSync table with encrypted columns, marks the sync as active with Provider "Microsoft", and displays "Outlook Calendar Connected" on SCR-013

### AC-03: Existing appointments are synced on first connect

- **Given**: The patient has upcoming appointments and has just connected Outlook Calendar
- **When**: The sync is activated
- **Then**: A background job creates Outlook calendar events for all upcoming appointments with correct date, time, provider, and location details

### AC-04: New bookings create calendar events automatically

- **Given**: The patient has an active Outlook Calendar sync
- **When**: The patient books a new appointment
- **Then**: A calendar event is created in the patient's Outlook calendar asynchronously via a Hangfire background job

### AC-05: Cancellations and reschedules update calendar events

- **Given**: The patient has an active Outlook Calendar sync
- **When**: An appointment is cancelled or rescheduled
- **Then**: The corresponding Outlook calendar event is deleted (cancellation) or updated (reschedule) via a background job

### AC-06: Token refresh handles expiry transparently

- **Given**: The patient's Microsoft OAuth access token has expired
- **When**: A calendar sync operation is attempted
- **Then**: The system uses the refresh token to obtain a new access token; if the refresh token is also expired, the patient is notified to re-authorize

### AC-07: Patient can disconnect Outlook Calendar

- **Given**: The patient has an active Outlook Calendar sync
- **When**: The patient clicks "Disconnect Outlook Calendar" on SCR-013
- **Then**: The sync is deactivated, stored tokens are deleted, and future appointment changes are no longer synced

## Edge Cases

- **Dual calendar connections**: If the patient connects both Google and Outlook calendars, each booking creates events in both calendars independently; failures in one do not block the other
- **Microsoft Graph API throttling**: If rate limits are hit, jobs are queued with exponential backoff and processed within available quota
- **OAuth consent revoked externally**: If the patient revokes calendar permissions through their Microsoft account settings, the next sync attempt should detect the revocation, deactivate the sync, and notify the patient to re-authorize
