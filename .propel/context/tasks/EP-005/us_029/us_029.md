# User Story - US_029

## Story ID

- ID Format: US_029

## Story Title

- AI Conversational Intake

## Description

- As a **patient**, I want to complete my pre-appointment intake using an AI-powered conversational chat interface that extracts structured medical data from my natural language responses, so that I can provide my medical history, symptoms, medications, and allergies in a convenient, guided format.

## Acceptance Criteria

### AC-01: Conversational intake launches for upcoming appointment

- **Given**: The patient navigates to the intake section for an upcoming appointment
- **When**: The patient selects "AI Conversational Intake" mode on SCR-009
- **Then**: The system initiates a chat interface with an opening message prompting the patient to describe their reason for visit

### AC-02: AI asks structured questions and extracts data

- **Given**: The conversational intake is active
- **When**: The patient responds to AI questions in natural language
- **Then**: The AI extracts structured data fields (medical history, current symptoms, medications, allergies, reason for visit) from responses and displays parsed results for the patient to confirm

### AC-03: Typing indicator during AI response generation

- **Given**: The patient has sent a message in the chat
- **When**: The AI is processing the response
- **Then**: A typing indicator animation (UXR-505) is displayed in the chat until the AI response is ready

### AC-04: Patient reviews and confirms extracted data

- **Given**: The AI has extracted structured data from the conversation
- **When**: The patient reviews the extracted summary
- **Then**: The patient can confirm each field as correct, edit incorrect fields inline, or flag fields for re-extraction

### AC-05: De-identified prompts sent to cloud LLM

- **Given**: The AI processes patient input
- **When**: Patient text is sent to the cloud LLM API (OpenAI/Gemini)
- **Then**: Only de-identified or patient-provided free-text is transmitted — no PHI from existing medical records, document extractions, or system-stored data is included in the LLM prompt

### AC-06: Intake data is stored linked to appointment

- **Given**: The patient confirms the extracted intake data
- **When**: The patient submits the completed intake
- **Then**: An IntakeRecord is created with IntakeMode "AI", linked to the appointment and patient profile, containing the structured medical data

## Edge Cases

- **AI cannot parse response**: If the AI fails to extract structured data from a patient message, it should ask a clarifying follow-up question with a rephrased prompt
- **Low confidence fields**: If the AI's confidence for a specific field is below the configurable threshold, the field is flagged with "Please verify" for the patient
- **Session interrupted**: If the patient's session expires mid-intake, data entered so far should be preserved in local storage and restored when the patient logs back in
