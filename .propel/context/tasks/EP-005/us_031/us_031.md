# User Story - US_031

## Story ID

- ID Format: US_031

## Story Title

- Intake Mode Toggle and AI Fallback

## Description

- As a **patient**, I want to freely toggle between AI conversational and manual form intake modes with all entered data preserved during the switch, and have the system automatically fall back to manual form when the AI service is unavailable, so that I never lose my progress and can always complete intake.

## Acceptance Criteria

### AC-01: Toggle from AI to manual preserves all data

- **Given**: The patient is using AI conversational intake and has provided responses that extracted structured data
- **When**: The patient clicks the "Switch to Manual Form" toggle
- **Then**: The manual form (SCR-010) opens pre-populated with all data extracted from the AI conversation; no re-entry is required

### AC-02: Toggle from manual to AI preserves all data

- **Given**: The patient is using manual form intake and has filled in several fields
- **When**: The patient clicks the "Switch to AI Chat" toggle
- **Then**: The AI conversational interface (SCR-009) opens with the previously entered data available as context; the AI acknowledges the existing data and continues from where the patient left off

### AC-03: Toggle button is visible on both intake screens

- **Given**: The patient is on either SCR-009 (AI intake) or SCR-010 (manual intake)
- **When**: The patient views the intake interface
- **Then**: A clearly labeled toggle control (UXR-105) is visible showing the current mode and the option to switch to the alternative mode

### AC-04: Auto-fallback to manual on AI service unavailability

- **Given**: The patient selects AI conversational intake or is in an active AI session
- **When**: The AI service (cloud LLM API) is unavailable or returns an error
- **Then**: The system automatically redirects the patient to the manual form (SCR-010) with a notification "AI intake is temporarily unavailable. Please continue with the manual form." and any data collected so far is preserved

### AC-05: Auto-fallback on AI processing timeout

- **Given**: The patient sends a message in the AI chat
- **When**: The AI does not respond within the configured timeout (e.g., 30 seconds)
- **Then**: The system displays "AI is taking too long to respond" with options: "Wait", "Retry", or "Switch to Manual Form"

### AC-06: Graceful degradation logged for monitoring

- **Given**: An AI fallback event occurs
- **When**: The system auto-switches to manual form
- **Then**: The event is logged with the error reason, timestamp, and patient session ID for monitoring and reliability tracking

## Edge Cases

- **Rapid toggle switching**: If the patient toggles between modes multiple times quickly, the system should debounce the toggle action and ensure data consistency across each switch
- **AI partially available**: If the AI service responds to some queries but fails on others, the system should flag individual failed fields for manual entry rather than falling back entirely
- **Data format mismatch**: If the AI extracts a date in a different format than the manual form expects, the toggle should normalize the data format during the switch
