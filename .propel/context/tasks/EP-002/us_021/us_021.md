# User Story - US_021

## Story ID

- ID Format: US_021

## Story Title

- Booking Confirmation PDF and Insurance Soft Validation

## Description

- As a **patient**, I want to receive a PDF confirmation of my booking details via email and optionally validate my insurance information against the platform's internal records during booking, so that I have a record of my appointment and can pre-verify insurance coverage.

## Acceptance Criteria

### AC-01: PDF confirmation is generated with appointment details

- **Given**: A patient has successfully booked an appointment
- **When**: The booking is confirmed
- **Then**: The system generates a PDF containing the provider name, specialty, appointment date and time, location, and booking reference number

### AC-02: PDF is sent to patient via email

- **Given**: A booking confirmation PDF has been generated
- **When**: The email delivery is triggered
- **Then**: The patient receives an email with the PDF attached within the async delivery pipeline, with retry on failure (max 3 attempts, exponential backoff)

### AC-03: Insurance name and ID are soft-validated

- **Given**: The patient is on the insurance form (SCR-014) during the booking flow
- **When**: The patient enters an insurance provider name and insurance ID
- **Then**: The system searches the internal InsuranceRecord table for a matching record and displays either "Insurance Verified" with matched provider details or "Insurance Not Found — this is a soft check and does not block your booking"

### AC-04: Insurance entry is optional and non-blocking

- **Given**: The patient is on the insurance form during booking
- **When**: The patient skips insurance entry
- **Then**: The booking proceeds without insurance validation and the patient profile stores null for insurance fields

### AC-05: Insurance validation unavailable does not block booking

- **Given**: The insurance validation query encounters a database error
- **When**: The validation is attempted
- **Then**: The system logs the error, allows the booking to proceed, and flags the insurance entry for later validation

## Edge Cases

- **PDF generation timeout**: If PDF generation takes longer than 10 seconds, the system should time out, create the appointment record anyway, and send a text-only email with a note that the PDF will follow
- **Large PDF**: If appointment details include special characters or long provider names, the PDF layout should handle text overflow gracefully with truncation or wrapping
- **Insurance ID format variations**: The soft validation should match against the InsuranceIdPattern column using pattern matching rather than exact string comparison
