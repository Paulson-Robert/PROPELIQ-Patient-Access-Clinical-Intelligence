# User Story - US_035

## Story ID

- ID Format: US_035

## Story Title

- ML.NET Clinical NER Pipeline

## Description

- As a **developer**, I want an ML.NET-based Named Entity Recognition pipeline that extracts clinical data (vitals, medications, allergies, diagnoses, procedures) from multi-format uploaded documents using format-specific parsers, so that patient clinical data is extracted automatically without transmitting PHI to external services.

## Acceptance Criteria

### AC-01: PDF documents are parsed and entities extracted

- **Given**: A clinical document in PDF format has passed malware scanning
- **When**: The document enters the extraction pipeline
- **Then**: The system uses iText7 to extract text, applies the ML.NET NER model to identify clinical entities (vitals, medications, allergies, diagnoses, procedures), and stores ExtractedDataRecord entries linked to the source document

### AC-02: DOCX documents are parsed and entities extracted

- **Given**: A clinical document in DOCX format has passed malware scanning
- **When**: The document enters the extraction pipeline
- **Then**: The system uses DocumentFormat.OpenXml to extract text, applies the ML.NET NER model, and stores ExtractedDataRecord entries

### AC-03: Image documents (JPG/PNG) use OCR before extraction

- **Given**: A clinical document in JPG or PNG format has passed malware scanning
- **When**: The document enters the extraction pipeline
- **Then**: The system uses Tesseract.NET for OCR to extract text from the image, applies the ML.NET NER model to the OCR output, and stores ExtractedDataRecord entries

### AC-04: DICOM metadata and embedded reports are extracted

- **Given**: A DICOM file has passed malware scanning
- **When**: The document enters the extraction pipeline
- **Then**: The system extracts metadata tags and any embedded diagnostic report text from the DICOM file (per CON-005 — no image rendering), applies NER to the report text, and stores extracted entities

### AC-05: HL7/FHIR bundles are deserialized and entities mapped

- **Given**: An HL7/FHIR bundle file has passed malware scanning
- **When**: The document enters the extraction pipeline
- **Then**: The system deserializes the FHIR bundle (read-only per CON-006), maps structured resources (Observation, MedicationStatement, AllergyIntolerance, Condition, Procedure) to ExtractedDataRecord entries

### AC-06: All extraction runs locally without PHI egress

- **Given**: Any document is being processed
- **When**: The NER pipeline executes
- **Then**: All processing occurs within the local application boundary using ML.NET; no PHI data is transmitted to any cloud API or external service

## Edge Cases

- **Corrupted or unreadable document**: If text extraction fails (corrupted PDF, unreadable image), the document is marked as "Extraction Failed — Manual Review Required" and flagged for staff review
- **Empty text extraction**: If OCR or text extraction produces no meaningful text (blank image, empty PDF), the document status is set to "No Data Extracted" with a notification to the patient
- **Mixed-language content**: Non-English text segments should be skipped with a log entry; the NER model processes English-language content only (per ASM-007)
