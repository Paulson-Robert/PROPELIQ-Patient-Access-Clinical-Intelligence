# User Story - US_036

## Story ID

- ID Format: US_036

## Story Title

- PHI Boundary Enforcement and Confidence Scoring

## Description

- As a **developer**, I want every AI-generated extraction to include a confidence score (0.0–1.0) with configurable thresholds for auto-suggestion vs mandatory review, and architectural enforcement that no PHI data leaves the local processing boundary, so that extraction quality is measurable and HIPAA PHI boundaries are maintained.

## Acceptance Criteria

### AC-01: Every extracted field has a confidence score

- **Given**: The ML.NET NER pipeline extracts clinical data from a document
- **When**: An ExtractedDataRecord is created
- **Then**: The Confidence field contains a value between 0.0 and 1.0 representing the model's certainty for that extraction

### AC-02: High-confidence extractions are auto-suggested for verification

- **Given**: An extracted field has a confidence score above the configurable high-confidence threshold (default: 0.85)
- **When**: The extraction results are presented to staff for verification
- **Then**: The field is displayed as a pre-filled suggestion with a "Verify" action, streamlining the review process

### AC-03: Low-confidence extractions are flagged for mandatory review

- **Given**: An extracted field has a confidence score below the configurable low-confidence threshold (default: 0.60)
- **When**: The extraction results are presented to staff for verification
- **Then**: The field is highlighted with a "Low Confidence — Manual Review Required" warning and the field cannot be auto-accepted

### AC-04: Confidence thresholds are configurable

- **Given**: The system administrator needs to adjust extraction sensitivity
- **When**: The high-confidence and low-confidence threshold values are updated in application configuration
- **Then**: All subsequent extraction processing uses the updated thresholds without requiring a redeployment

### AC-05: PHI boundary is enforced at the infrastructure level

- **Given**: A document containing PHI is being processed
- **When**: Any processing code attempts to transmit PHI data to an external service
- **Then**: The PHI boundary middleware blocks the outbound request and logs a security violation — ensuring only the local ML.NET pipeline processes PHI

### AC-06: Extraction results include source location references

- **Given**: The NER pipeline extracts a clinical entity
- **When**: The ExtractedDataRecord is stored
- **Then**: The SourceLocation field identifies where in the source document the entity was found (page number, paragraph, or character offset)

## Edge Cases

- **All extractions below low-confidence**: If every field in a document is below the low-confidence threshold, the entire document should be flagged for full manual review with a "Low extraction quality" warning
- **Confidence score exactly on threshold boundary**: A confidence score exactly equal to the threshold should be treated as meeting the threshold (inclusive comparison)
- **Configuration hot-reload**: Threshold configuration changes should be applied without restarting the application, using IOptionsMonitor or similar pattern
