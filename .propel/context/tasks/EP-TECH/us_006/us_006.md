# User Story - US_006

## Story ID

- ID Format: US_006

## Story Title

- CI/CD Pipeline and Deployment Infrastructure

## Description

- As a **developer**, I want automated CI/CD pipelines deploying the frontend to Vercel, backend to Railway or Render, and database provisioned on Supabase, so that every merged change is automatically built, tested, and deployed to a live environment using only free-tier infrastructure.

## Acceptance Criteria

### AC-01: Frontend deploys to Vercel on push to main

- **Given**: The frontend project (US_001) is committed to the repository and Vercel is connected to the Git repository
- **When**: A developer pushes a commit to the `main` branch
- **Then**: Vercel automatically triggers a build, runs `pnpm build`, deploys the static assets to a public URL, and the deployment completes within 5 minutes with a success status in the Vercel dashboard

### AC-02: Backend deploys to Railway or Render on push to main

- **Given**: The backend project (US_002) is committed to the repository with a `Dockerfile` and the hosting platform is connected
- **When**: A developer pushes a commit to the `main` branch
- **Then**: The platform builds the Docker container, deploys it, and the API responds to `GET /health` with HTTP 200 at the deployed URL within 10 minutes of the push

### AC-03: Supabase PostgreSQL is provisioned and accessible

- **Given**: A Supabase project is created with free-tier plan
- **When**: The backend application starts with the Supabase connection string configured
- **Then**: EF Core connects to the Supabase PostgreSQL instance, confirms `CanConnect() == true`, and the pgcrypto extension is available

### AC-04: CI pipeline runs build and test on pull requests

- **Given**: A GitHub Actions workflow is configured for the repository
- **When**: A developer opens a pull request targeting `main`
- **Then**: The CI pipeline triggers, runs `dotnet build`, `dotnet test`, `pnpm build`, and `pnpm test` in parallel, and reports pass/fail status as a GitHub check on the PR within 10 minutes

### AC-05: Environment variables and secrets are securely managed

- **Given**: The deployment platforms (Vercel, Railway/Render) are configured
- **When**: Secrets (database connection string, Sentry DSN, API keys) are added to platform environment variable settings
- **Then**: Secrets are encrypted at rest by the platform, not committed to the repository, and accessible to the application at runtime via environment variables without appearing in build logs

### AC-06: All deployment platforms use free-tier plans

- **Given**: The deployment infrastructure is fully configured
- **When**: The platform billing dashboards are reviewed
- **Then**: All three platforms (Vercel, Railway/Render, Supabase) show free-tier usage with zero charges and no credit card requirements for the configured resource levels

## Edge Cases

- **Build timeout**: If the CI build exceeds 10 minutes (GitHub Actions free-tier limit for public repos), the workflow should fail with a descriptive timeout message rather than consuming remaining minutes silently
- **Free-tier resource limits**: If Supabase approaches the 500 MB storage limit, the health check should report `Degraded` status with a log warning indicating remaining capacity
- **Deployment rollback**: If a deployment fails health checks post-deploy, the platform should retain the previous working deployment and not serve the broken build
