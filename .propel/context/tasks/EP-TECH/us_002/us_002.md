# User Story - US_002

## Story ID

- ID Format: US_002

## Story Title

- Backend API Scaffold with Clean Architecture

## Description

- As a **developer**, I want a fully configured ASP.NET Core 9 backend solution with Clean Architecture layers and MediatR command/query separation, so that all backend feature development follows a consistent, testable, and maintainable architecture.

## Acceptance Criteria

### AC-01: Solution builds with Clean Architecture layer separation

- **Given**: A clean development environment with .NET 9 SDK installed
- **When**: The developer runs `dotnet build` on the solution
- **Then**: The solution compiles successfully with four distinct projects: API (presentation), Application (business logic/MediatR handlers), Domain (entities/value objects), and Infrastructure (data access/external services), each with correct project references enforcing dependency flow (API → Application → Domain; Infrastructure → Application → Domain)

### AC-02: API project starts and responds to health check

- **Given**: The backend solution is built
- **When**: The developer runs `dotnet run` on the API project
- **Then**: The API starts on the configured port and responds with HTTP 200 to `GET /health` within 2 seconds of startup, returning a JSON body with `{ "status": "Healthy" }`

### AC-03: MediatR pipeline processes a sample command

- **Given**: The API project is running with MediatR configured
- **When**: A sample `PingCommand` is dispatched via a test endpoint `POST /api/ping`
- **Then**: MediatR routes the command to its handler, the handler executes, and the endpoint returns HTTP 200 with `{ "message": "pong" }` confirming the pipeline is functional

### AC-04: Dependency injection is configured across all layers

- **Given**: The solution is built with all NuGet packages restored
- **When**: The API starts and resolves services from the DI container
- **Then**: All registered services (MediatR handlers, infrastructure services, configuration objects) resolve without `InvalidOperationException` and the DI container reports zero unresolved dependencies at startup

### AC-05: All dependencies are free and open-source

- **Given**: The backend solution scaffold is complete
- **When**: The NuGet package licenses are audited via `dotnet list package`
- **Then**: All packages use OSI-approved open-source licenses (MIT, Apache 2.0, .NET Library License) with zero proprietary or paid dependencies

## Edge Cases

- **.NET SDK version mismatch**: If .NET SDK < 9.0 is installed, `dotnet build` should fail with a clear `global.json` error message specifying the required SDK version
- **NuGet restore failure behind proxy**: If corporate proxy blocks NuGet.org, the solution should include a `nuget.config` with fallback source configuration instructions
- **Port conflict**: If the configured port is occupied, Kestrel should log the conflict and fail fast with a descriptive error rather than silently binding to a random port
