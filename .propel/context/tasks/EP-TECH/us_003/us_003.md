# User Story - US_003

## Story ID

- ID Format: US_003

## Story Title

- Database and ORM Configuration with PostgreSQL

## Description

- As a **developer**, I want Entity Framework Core 9 configured with PostgreSQL and pgcrypto, using a hybrid migration strategy, so that all domain entities can be persisted with field-level encryption support and migrations are safe for production.

## Acceptance Criteria

### AC-01: EF Core connects to PostgreSQL and runs initial migration

- **Given**: A PostgreSQL 16 instance is running (local or Supabase) and the connection string is configured in `appsettings.Development.json`
- **When**: The developer runs `dotnet ef database update` from the Infrastructure project
- **Then**: EF Core applies the initial migration, creates the `__EFMigrationsHistory` table, and the database is accessible via the configured connection string with zero migration errors

### AC-02: pgcrypto extension is enabled

- **Given**: The initial migration has been applied to the PostgreSQL database
- **When**: The developer queries `SELECT * FROM pg_extension WHERE extname = 'pgcrypto'`
- **Then**: The query returns exactly one row confirming pgcrypto is installed and active, enabling `pgp_sym_encrypt` and `pgp_sym_decrypt` functions

### AC-03: Hybrid migration strategy is documented and enforced

- **Given**: The EF Core migration infrastructure is configured
- **When**: A developer creates a new migration via `dotnet ef migrations add <name>`
- **Then**: The migration C# file is generated in the Infrastructure project's `Migrations/` folder, and a corresponding reviewed SQL script can be exported via `dotnet ef migrations script` for production deployment

### AC-04: Database context resolves through dependency injection

- **Given**: The API project is running
- **When**: A service constructor requests `ApplicationDbContext` via DI
- **Then**: The DI container resolves the context with a valid PostgreSQL connection, and a simple query (e.g., `context.Database.CanConnect()`) returns `true`

### AC-05: Connection uses only free-tier compatible configuration

- **Given**: The database connection string targets a Supabase PostgreSQL instance
- **When**: The application connects and runs the initial migration
- **Then**: The connection succeeds within Supabase free-tier limits (500 MB storage, connection pooling via Supavisor) with no paid add-on requirements

## Edge Cases

- **PostgreSQL connection failure**: If the database is unreachable, the application should log a descriptive error with connection details (host, port, database name — never credentials) and fail fast at startup rather than accepting requests that will error
- **pgcrypto not available**: If the hosting provider does not support pgcrypto, the migration should fail with a clear error message indicating the extension requirement rather than silently skipping encryption
- **Concurrent migration execution**: If two developers run migrations simultaneously, EF Core's migration lock should prevent duplicate or conflicting migrations
