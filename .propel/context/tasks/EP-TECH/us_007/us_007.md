# User Story - US_007

## Story ID

- ID Format: US_007

## Story Title

- Testing Framework Setup Across All Layers

## Description

- As a **developer**, I want xUnit, Vitest, and Playwright testing frameworks configured with sample tests passing, so that all feature development has automated testing infrastructure from day one.

## Acceptance Criteria

### AC-01: xUnit backend test project builds and runs sample test

- **Given**: The backend solution includes a test project referencing xUnit, FluentAssertions, and Moq NuGet packages
- **When**: The developer runs `dotnet test` from the solution root
- **Then**: The test runner discovers and executes at least one sample unit test (e.g., `PingCommandHandler_Returns_Pong`), the test passes, and the console output reports `Passed: 1, Failed: 0`

### AC-02: Vitest frontend test runner executes sample component test

- **Given**: The frontend project includes Vitest and React Testing Library as dev dependencies
- **When**: The developer runs `pnpm test` in the frontend project
- **Then**: Vitest discovers and executes at least one sample component test (e.g., `renders App component`), the test passes, and the console output reports the pass count with zero failures

### AC-03: Playwright E2E configuration is functional

- **Given**: Playwright is installed with browser binaries downloaded (`npx playwright install`)
- **When**: The developer runs `npx playwright test` with a sample E2E test that navigates to the frontend dev server root and asserts the page title
- **Then**: The test executes in headless Chromium, passes, and generates an HTML test report in the `playwright-report/` directory

### AC-04: Test projects follow standard directory conventions

- **Given**: The test infrastructure is fully configured
- **When**: the developer inspects the project structure
- **Then**: Backend tests reside in `tests/` at the solution root with naming convention `*.Tests` (e.g., `Application.Tests`, `API.Tests`); frontend tests reside in `src/**/__tests__/` or `src/**/*.test.tsx`; Playwright tests reside in `e2e/` at the frontend project root

### AC-05: All testing dependencies are free and open-source

- **Given**: The test framework setup is complete
- **When**: Package licenses are audited
- **Then**: All testing packages (xUnit, FluentAssertions, Moq, Vitest, React Testing Library, Playwright) use OSI-approved open-source licenses with zero paid dependencies

## Edge Cases

- **Playwright browser download failure**: If Playwright cannot download browser binaries (network restriction), the setup should log the failure with manual download instructions and not block other test frameworks from functioning
- **Test runner version conflicts**: If xUnit and FluentAssertions have incompatible version ranges, `dotnet restore` should fail with a clear NuGet version conflict message rather than silently downgrading
- **Parallel test execution collision**: If multiple test classes access shared resources, test isolation should be enforced via `IClassFixture<>` or test-specific database contexts to prevent flaky test failures
