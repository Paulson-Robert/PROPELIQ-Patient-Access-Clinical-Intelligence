# User Story - US_010

## Story ID

- ID Format: US_010

## Story Title

- Clinical Document Storage and Medical Code Reference Tables

## Description

- As a **developer**, I want the database schema configured to support multi-format clinical document storage metadata and versioned ICD-10-CM/CPT-4 reference code tables, so that the document processing pipeline and code mapping features have the required data structures.

## Acceptance Criteria

### AC-01: ClinicalDocument entity supports all required formats

- **Given**: The ClinicalDocument entity is configured in the database
- **When**: A document record is created with FileFormat set to any of PDF, DOCX, JPG, PNG, DICOM, or HL7/FHIR
- **Then**: The record is persisted successfully with the format value stored as a validated enum or constrained string column

### AC-02: Document processing status tracks pipeline stages

- **Given**: A ClinicalDocument record exists
- **When**: The document progresses through pipeline stages
- **Then**: The ProcessingStatus column correctly transitions through Uploading, Scanning, Processing, Completed, and Failed states with timestamps recorded at each transition

### AC-03: ICD-10-CM reference table is seeded with version tracking

- **Given**: The database migration includes the ICD-10 reference table schema
- **When**: The seed data script executes
- **Then**: The ICD-10-CM code table contains a representative set of codes with columns for CodeValue, Description, Category, and CodeSetVersion, and the version column supports annual code set updates

### AC-04: CPT-4 reference table is seeded with version tracking

- **Given**: The database migration includes the CPT reference table schema
- **When**: The seed data script executes
- **Then**: The CPT-4 code table contains a representative set of codes with columns for CodeValue, Description, Category, and CodeSetVersion, supporting independent versioning from ICD-10

### AC-05: MedicalCodeMapping links to versioned code sets

- **Given**: A MedicalCodeMapping record is created
- **When**: The mapping references an ICD-10 or CPT code
- **Then**: The CodeSetVersion field on the mapping matches the version of the reference table used, enabling traceability across annual code set updates

## Edge Cases

- **Duplicate code entries across versions**: Reference tables should allow the same CodeValue to exist in different CodeSetVersion entries without unique constraint violations
- **DICOM metadata-only storage**: DICOM records should store metadata and embedded report text references without requiring full image binary storage in the database (per CON-005)
- **Empty code tables**: If seed data is not yet loaded, code mapping queries should return empty results rather than throwing exceptions
