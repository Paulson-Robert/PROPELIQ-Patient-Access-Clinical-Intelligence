# User Story - US_008

## Story ID

- ID Format: US_008

## Story Title

- Core Database Schema and Entity Configuration

## Description

- As a **developer**, I want the PostgreSQL database schema established with EF Core entity configurations for all domain entities, pgcrypto field-level encryption on PHI columns, and JSONB column support for aggregated clinical data, so that all feature epics have a consistent, HIPAA-compliant data foundation to build upon.

## Acceptance Criteria

### AC-01: EF Core DbContext registers all domain entities

- **Given**: The backend project with EF Core configured (US_003)
- **When**: A developer runs `dotnet ef migrations add InitialSchema`
- **Then**: The migration is generated successfully containing table definitions for User, PatientProfile, Appointment, AvailabilitySlot, PreferredSlotQueue, ClinicalDocument, ExtractedDataRecord, DataConflict, PatientView, MedicalCodeMapping, IntakeRecord, Notification, CalendarSync, AuditLog, NoShowRiskFactor, and InsuranceRecord

### AC-02: PHI columns use pgcrypto field-level encryption

- **Given**: The migration has been applied to a PostgreSQL 16 database with pgcrypto extension enabled
- **When**: A PatientProfile record is inserted with FirstName, LastName, DateOfBirth, and Phone values
- **Then**: The stored column values in the database are encrypted at rest using pgcrypto symmetric encryption (AES-256) and are only readable through the application's Data Protection API decryption path

### AC-03: JSONB columns are configured for aggregated data

- **Given**: The PatientView entity is configured in EF Core
- **When**: A PatientView record is inserted with AggregatedVitals, AggregatedMedications, AggregatedAllergies, AggregatedDiagnoses, and AggregatedProcedures data
- **Then**: Each aggregated field is stored as a JSONB column in PostgreSQL, supporting native JSON query operators and indexing

### AC-04: Entity relationships and foreign keys are enforced

- **Given**: The database schema is applied
- **When**: A developer attempts to insert an Appointment record with a non-existent PatientId
- **Then**: The database rejects the insert with a foreign key constraint violation error

### AC-05: Data conflict tracking schema supports multi-document conflicts

- **Given**: The DataConflict entity is configured
- **When**: Two documents contain conflicting medication values for the same patient
- **Then**: A DataConflict record can be created linking both source document IDs, the conflicting field name, both values, and a resolution status of "Open"

## Edge Cases

- **pgcrypto extension not installed**: Migration should fail with a clear error indicating the pgcrypto extension must be enabled via `CREATE EXTENSION IF NOT EXISTS pgcrypto`
- **JSONB null handling**: JSONB columns should accept null values for patients with no aggregated data yet, without throwing serialization errors
- **Concurrent migration execution**: If two migration runs occur simultaneously, EF Core's migration lock should prevent duplicate schema changes
