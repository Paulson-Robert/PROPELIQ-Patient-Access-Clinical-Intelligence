# User Story - US_046

## Story ID

- ID Format: US_046

## Story Title

- Admin Platform Metrics Dashboard

## Description

- As an **admin**, I want a dashboard displaying platform adoption metrics (total patient dashboards created, total appointments booked, current no-show rate) with trend data over time and date range filtering, so that I can monitor platform usage and identify operational trends.

## Acceptance Criteria

### AC-01: Dashboard displays key adoption metrics

- **Given**: The admin navigates to the admin dashboard (SCR-004) or the platform metrics page (SCR-025)
- **When**: The page loads
- **Then**: The system displays metric cards showing: total patient accounts created, total appointments booked, current no-show rate (percentage), and total documents processed

### AC-02: Trend charts show metric history

- **Given**: The admin views the platform metrics page (SCR-025)
- **When**: The metrics section loads
- **Then**: Line or bar charts display trend data over time for each metric (daily, weekly, or monthly granularity)

### AC-03: Date range filter updates all metrics

- **Given**: The admin is viewing platform metrics
- **When**: The admin selects a custom date range (start date, end date)
- **Then**: All metric cards and trend charts update to reflect only data within the selected range

### AC-04: Zero-state for new deployment

- **Given**: The platform is newly deployed with no data
- **When**: The admin views the metrics dashboard
- **Then**: All metrics display zero values with a "No data yet — metrics will appear as the platform is used" message

### AC-05: No-show rate calculation is accurate

- **Given**: The platform has completed appointments
- **When**: The no-show rate metric is calculated
- **Then**: The rate equals (No-Show appointments / Total completed + No-Show appointments) × 100, excluding Cancelled and Scheduled appointments from the denominator

## Edge Cases

- **Large date range**: If the admin selects a date range spanning years, the trend chart should aggregate to monthly granularity to maintain readability
- **Real-time vs. cached metrics**: Metrics may be computed from cached aggregations updated periodically (e.g., every 15 minutes) rather than real-time queries, to avoid performance impact on the production database
- **Metric count overflow**: If total appointments exceed display space (e.g., 1,234,567), numbers should be formatted with appropriate abbreviation (1.2M) or thousands separators
