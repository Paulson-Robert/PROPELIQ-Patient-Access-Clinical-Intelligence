# User Story - US_045

## Story ID

- ID Format: US_045

## Story Title

- Audit Log Viewer

## Description

- As an **admin**, I want a searchable, filterable, paginated audit log viewer, so that I can review system activity for compliance investigations and security monitoring.

## Acceptance Criteria

### AC-01: Audit log viewer displays recent entries by default

- **Given**: The admin navigates to the audit log viewer (SCR-024)
- **When**: The page loads
- **Then**: The system displays the most recent audit log entries (newest first) in a paginated table with columns for timestamp, actor, action type, resource type, resource ID, and a details preview

### AC-02: Admin filters by date range

- **Given**: The admin is on the audit log viewer
- **When**: The admin sets a start date and end date filter
- **Then**: The results are filtered to show only entries within the specified date range

### AC-03: Admin filters by actor

- **Given**: The admin is on the audit log viewer
- **When**: The admin enters a user email or ID in the actor filter
- **Then**: The results are filtered to show only entries where the specified user was the actor

### AC-04: Admin filters by action type

- **Given**: The admin is on the audit log viewer
- **When**: The admin selects an action type filter (e.g., "LoginFailed", "PatientDataAccessed", "UserDeactivated")
- **Then**: The results are filtered to show only entries matching the selected action type

### AC-05: Pagination handles large result sets

- **Given**: The audit log contains thousands of entries
- **When**: The admin views the log with or without filters
- **Then**: Results are paginated (50 per page) with page navigation controls and a total count display

### AC-06: No results shows filter summary

- **Given**: The admin applies filter criteria
- **When**: No audit log entries match the filters
- **Then**: The system displays "No entries found" with a summary of the applied filters and a "Clear Filters" button

## Edge Cases

- **Extremely large detail fields**: If the Details JSONB column contains very large payloads, the table should show a truncated preview with a "View Full Details" expandable section
- **Concurrent audit entries**: If new audit entries are created while the admin is viewing the log, the view should not jump or refresh — the admin can click "Refresh" to see new entries
- **Admin cannot modify entries**: The viewer must be read-only — no edit, delete, or bulk action buttons should exist on the audit log viewer
