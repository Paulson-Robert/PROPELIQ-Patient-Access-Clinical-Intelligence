# User Story - US_043

## Story ID

- ID Format: US_043

## Story Title

- Admin User Management

## Description

- As an **admin**, I want to create, update, and deactivate user accounts with role assignments, so that I can manage platform access for staff and admin users with proper role-based permissions.

## Acceptance Criteria

### AC-01: Admin creates a new user account

- **Given**: The admin is on the user management page (SCR-023)
- **When**: The admin clicks "Create User", enters email and assigns a role (Staff or Admin) via the create/edit modal (MOD-004)
- **Then**: A new user account is created with "Pending Activation" status and an activation email is sent to the new user

### AC-02: Admin updates user role

- **Given**: The admin views an existing user in the user management list
- **When**: The admin edits the user's role (e.g., Staff → Admin)
- **Then**: The role change is applied immediately — the user's next API request uses the new role permissions

### AC-03: Admin deactivates a user account

- **Given**: The admin views an active user account
- **When**: The admin clicks "Deactivate" and confirms
- **Then**: The account status changes to "Inactive", all active sessions for that user are invalidated, and the deactivated user cannot log in

### AC-04: Last admin account cannot be deactivated

- **Given**: Only one active admin account exists
- **When**: An admin attempts to deactivate that account
- **Then**: The system prevents the action with "At least one admin account must remain active" and the account stays active

### AC-05: User management list displays key information

- **Given**: The admin navigates to the user management page (SCR-023)
- **When**: The page loads
- **Then**: The system displays a table with columns for email, role, status (Active/Inactive/Pending), last login date, and action buttons (Edit, Deactivate/Activate)

### AC-06: Activation email failure is retried and reported

- **Given**: The admin creates a new user account
- **When**: The activation email delivery fails
- **Then**: The system retries delivery (max 3 attempts with exponential backoff) and displays the delivery status to the admin in the user management list

## Edge Cases

- **Duplicate email**: Creating a user with an email that already exists should display "An account with this email already exists" error
- **Self-deactivation**: An admin should not be able to deactivate their own account — the system should prevent this with a "You cannot deactivate your own account" message
- **Reactivation**: An admin should be able to reactivate a previously deactivated account, restoring its status to "Active" and allowing the user to log in again
